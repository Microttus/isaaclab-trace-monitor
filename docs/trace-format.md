# Trace format

IsaacLab Trace Monitor reads a bounded directory generated by the reference
`ObjectTraceCallback`.

## Directory layout

```text
object_traces/
├── metadata.json
├── episode_summary.csv
├── live/
│   ├── status.json
│   ├── env_000_current.csv
│   └── env_000_latest.csv
└── episodes/
    └── env_000/
        ├── episode_000012.csv
        └── episode_000013.csv
```

`env_000_current.csv` is atomically replaced while the episode is running.
`env_000_latest.csv` contains the newest completed trajectory. The `episodes/`
directory is optional and retention-bounded.

## Metadata

`metadata.json` is a JSON object. Important fields are:

| Field | Meaning |
|---|---|
| `format_version` | Integer format revision |
| `objects` | List of object names, CSV prefixes, and item indices |
| `env_ids` | Traced vectorized environment IDs |
| `coordinate_frame` | Human-readable position-frame description |
| `position_units` | Normally `m` |
| `quaternion_order` | `wxyz` when orientation is logged |
| `simulation_step_dt_s` | Simulated seconds per environment step |
| `include_actions` | Whether action columns are present |
| `columns` | Ordered trace-column list |

Positions are normally expressed in world-axis directions with the selected
environment origin subtracted. Orientations remain world-axis orientations.

## Trace CSV

A trace CSV contains one complete sampled scene state per row. The reference
logger writes these common fields:

| Column | Meaning |
|---|---|
| `global_step` | SB3 total timestep counter across vectorized environments |
| `callback_call` | Number of vectorized environment steps observed |
| `rollout` | PPO rollout index |
| `wall_time_s` | Wall time since callback start |
| `env_id` | Traced vectorized environment |
| `episode` | Episode index within that environment |
| `sample_index` | Dense row index after adaptive thinning |
| `episode_step` | Control step within the episode |
| `reward` | Reward visible to the SB3 callback |
| `episode_return` | Cumulative sum of the same reward value |
| `terminal` | `1` for a terminated terminal sample |
| `timeout` | `1` for a time-limit terminal sample |
| `termination_reason` | Optional textual reason |

Each object contributes:

```text
<object>_x
<object>_y
<object>_z
<object>_qw
<object>_qx
<object>_qy
<object>_qz
```

Quaternion order is `(w, x, y, z)`. Orientation columns are optional. If action
logging is enabled, columns are named `action_0`, `action_1`, and so on.

The minimum monitor-compatible object representation is a complete XYZ triplet:

```text
<object>_x,<object>_y,<object>_z
```

## Episode summary

`episode_summary.csv` contains one row per completed traced episode. The
reference logger writes:

```text
global_step,wall_time_s,rollout,env_id,episode,episode_return,
episode_length,samples,terminated,timeout,success,termination_reason,file
```

`success` may be empty/NaN when the environment does not expose a success flag.

## Status

`live/status.json` is an atomically replaced JSON object containing global
training state and one nested record per traced environment. The monitor uses
it for progress, rollout, episode, return, sample-count, and file-status fields.

## Terminal state correctness

Isaac Lab can reset a completed sub-environment before SB3's callback observes
the returned state. The reference callback therefore captures requested poses
at the recorder manager's pre-reset stage. The completed file ends with that
pre-reset pose and the new current file begins with the reset pose.

When the pre-reset hook is unavailable, the logger preserves the newest sampled
pose and records `terminal_pose_unavailable` in `termination_reason`.

## Atomic writing

Writers should create a temporary file in the target directory and replace the
final file atomically. This prevents the live monitor from parsing a partially
written CSV or JSON file.
